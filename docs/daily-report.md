# 전일 종합

대시보드 `/dashboard#daily`에서 전날(한국시간) 자사·경쟁사 후기를 확인한다.
매일 Asia/Seoul 09:00 APScheduler 작업이 `data/daily_reports/YYYY-MM-DD.json`을 원자적으로 저장한다.
재시작 후 당일 오전 9시 이후 생성본이 없으면 보충 생성한다. 오전 9시 전 조회는 전일 자료의 임시 집계이며 9시에 다시 생성된다.
API `/api/daily-report`는 해당 생성본과 다음 실행 시각을 반환한다.

브랜드: 백년화편, 명가삼대떡집.
전체 수집 여부가 검증되지 않으므로 모든 수치는 수집된 자료 기준이다. 네이버 자동 수집 미확인 상태도 명시한다.
중복 키는 기존 대시보드 정책과 같은 작성자·날짜·본문 앞 100자다.
평균 및 저평점은 유효한 1~5점만 사용한다. 3점 이하를 저평점으로 분류한다.
화면에는 브랜드별 전체 본문을 글자 수 내림차순으로 표시한다.
밑줄·형광펜 강조는 표시하지 않는다. 어떤 LLM API도 호출하지 않는다.

PNG 저장은 대시보드에 이미 있는 html2canvas를 사용해 사용자의 브라우저에서 한 장으로 생성한다.
카카오톡 전송 기능은 없다. 사용자는 이미지를 저장해 공유할 수 있다.

## 날짜별 누적 보관
보고서는 영구 볼륨에 날짜별 파일로 누적되며 과거 파일을 자동 삭제하지 않는다.
`GET /api/daily-report/dates`는 실제 저장된 날짜만 반환한다.
`GET /api/daily-report?date=YYYY-MM-DD`로 과거 스냅샷을 그대로 조회하며 조회 시 과거 보고서를 재작성하지 않는다.
최신 보고서는 기존 오전 9시 갱신 규칙을 따른다. 저장을 시작하기 전 날짜는 임의 복원하지 않는다.
`POST /api/daily-report/refresh`는 현재 전일 보고서만 현재 저장된 후기 기준으로 즉시 재생성한다.
이 동작은 네이버 등 외부 사이트를 재수집하지 않는다. 과거 날짜 선택은 API/파일명 모두 검증한다.

## 전체 후기 보기 (v2)
전일 종합에는 백년화편과 명가삼대떡집만 표시한다. 브랜드별 건수와 전체 본문을 모두 저장하며 3건 선택/180자 발췌 제한을 없앴다.
강조 표시를 제거했다. 과거 저장본도 화면에서 글자 수 내림차순으로 정렬하며 요약 이미지는 가장 긴 후기부터 선택한다.
전체 후기는 화면에서 모두 읽을 수 있다. 수백 건을 한 장 이미지로 축소하지 않도록 이미지 저장은 요약 3건/브랜드이며 버튼에 요약이라고 표시한다.
구버전 과거 보고서 원본은 유지한다. 구버전 선택 시 현재 저장된 해당 날짜 전체 자료로 재구성해 보여주고 그 사실을 표시한다.
