# 전일 종합

대시보드 `/dashboard#daily`에서 전날(한국시간) 자사·경쟁사 후기를 확인한다.
매일 Asia/Seoul 09:00 APScheduler 작업이 `data/daily_reports/YYYY-MM-DD.json`을 원자적으로 저장한다.
재시작 후 당일 오전 9시 이후 생성본이 없으면 보충 생성한다. 오전 9시 전 조회는 전일 자료의 임시 집계이며 9시에 다시 생성된다.
API `/api/daily-report`는 해당 생성본과 다음 실행 시각을 반환한다.

브랜드: 백년화편, 명가삼대떡집.
전체 수집 여부가 검증되지 않으므로 모든 수치는 수집된 자료 기준이다. 네이버 자동 수집 미확인 상태도 명시한다.
중복 키는 기존 대시보드 정책과 같은 작성자·날짜·본문 앞 100자다.
평균 및 저평점은 유효한 1~5점만 사용한다. 3점 이하를 저평점으로 분류한다.
화면에는 브랜드별 전체 본문을 글자 수 내림차순으로 표시한다.
밑줄·형광펜 강조는 표시하지 않는다. 어떤 LLM API도 호출하지 않는다.

PNG 저장은 대시보드에 이미 있는 html2canvas를 사용해 사용자의 브라우저에서 한 장으로 생성한다.
카카오톡 전송 기능은 없다. 사용자는 이미지를 저장해 공유할 수 있다.

## 날짜별 누적 보관
보고서는 영구 볼륨에 날짜별 파일로 누적되며 과거 파일을 자동 삭제하지 않는다.
`GET /api/daily-report/dates`는 실제 저장된 날짜만 반환한다.
`GET /api/daily-report?date=YYYY-MM-DD`로 과거 스냅샷을 그대로 조회하며 조회 시 과거 보고서를 재작성하지 않는다.
최신 보고서는 기존 오전 9시 갱신 규칙을 따른다. 저장을 시작하기 전 날짜는 임의 복원하지 않는다.
`POST /api/daily-report/refresh`는 현재 전일 보고서만 현재 저장된 후기 기준으로 즉시 재생성한다.
이 동작은 네이버 등 외부 사이트를 재수집하지 않는다. 과거 날짜 선택은 API/파일명 모두 검증한다.

## 전체 후기 보기 (v2)
전일 종합에는 백년화편과 명가삼대떡집만 표시한다. 브랜드별 건수와 전체 본문을 모두 저장하며 3건 선택/180자 발췌 제한을 없앴다.
강조 표시를 제거했다. 과거 저장본도 화면에서 글자 수 내림차순으로 정렬하며 요약 이미지는 가장 긴 후기부터 선택한다.
전체 후기는 화면에서 모두 읽을 수 있다. 수백 건을 한 장 이미지로 축소하지 않도록 이미지 저장은 요약 3건/브랜드이며 버튼에 요약이라고 표시한다.
구버전 과거 보고서 원본은 유지한다. 구버전 선택 시 현재 저장된 해당 날짜 전체 자료로 재구성해 보여주고 그 사실을 표시한다.

## 자사몰 수집 주기
한국시간 매시 06분 자사몰 후기를 수집한다. 00:06에는 기존 전체 수집 작업에 포함하고, 01:06~23:06에는 자사몰만 수집한다. 중복 실행은 기존 실행 잠금으로 막는다. 네이버 자정 수집과 전일 종합 09:00 생성 일정은 별도다.

## 전체 이미지 저장
브랜드별 3건/220자 발췌를 제거했다. 전체 본문을 글자 수 내림차순으로 렌더링한다. 긴 보고서는 높이 4,000px 단위 PNG로 분할해 번호 순서대로 ZIP 한 파일에 저장한다. 1장이면 PNG로 저장한다. 전체 높이 캔버스를 만들지 않아 브라우저 최대 캔버스 크기로 인한 누락을 방지한다.

## 카톡용 복사 요약

전일 종합 위쪽의 별도 요약 영역에서 날짜 범위·월·브랜드를 선택하고, 편집 가능한 텍스트를 복사한다. 최초 범위는 현재 선택한 전일 보고서(월요일은 금~일)를 따른다. 기간 선택은 아래 보관 보고서와 이미지 저장을 바꾸지 않는다. 카카오톡에 직접 전송하지 않는다.

`GET /api/review-copy-summary?date_from=YYYY-MM-DD&date_to=YYYY-MM-DD&brand=all|jasaol|myeongga`는 읽기 전용이다. 수집·보고서 갱신·보관본 수정·원격 AI API를 실행하지 않는다.

- 숫자와 문구 요약은 현재 저장된 기간 내 **전체 원문**을 사용한다. `/api/data`의 최대 500개 미리보기나 전일 종합의 선정 후기에서 집계하지 않는다
- 백년화편은 자사몰 원본의 `direct/naver/kakao`(네이버페이 등 결제 경로)이며, 별도 파일에서 `smartstore`로 정규화된 스마트스토어 후기는 제외한다
- 실제 `review_no/review_id/id`가 있을 때만 출처별 중복을 제거한다. ID 없는 동일한 본문은 다른 고객의 후기일 수 있으므로 보존한다. 이 때문에 기존 보관 보고서의 구형 중복 정책과 건수가 다를 수 있다
- 1~5의 유한 별점만 평균·3점 이하 비율에 사용한다. 0점·미제공 등 제외 건수는 총 후기 수와 분리해 복사 문구에 표시한다
- 긍정/불만·개선 주제는 원문 표현으로만 분류한다. 3점 이하라는 이유로 불만을 만들지 않고, 4~5점의 불만도 포함한다. 낮은 별점에 긍정 문구만 확인되면 별도 확인 항목으로 표시한다
- 주제별 건수는 같은 후기 안에서는 한 번만 세며, 한 후기가 여러 주제에 해당할 수 있다. 긍정 상위 4개, 확인 포인트 상위 6개와 주제 다양성·중요도를 고려한 대표 원문 최대 8건을 보여 준다. 전체 확인 표현 후기 수를 함께 표시한다
- 발췌는 고객 주장으로 표시한다. 규칙 기반 분류의 누락·문맥 오류 가능성을 안내하고 수정할 수 있게 한다. 전화번호·이메일 등 명시적 개인정보는 복사 발췌에서 가린다
- 입력을 고친 뒤 새로 생성할 때는 덮어쓰기를 확인한다. 오래된 응답은 새 기간·브랜드를 덮어쓰지 않으며, 조회 중·오류·기간 불일치·후기 없음 상태에는 복사하지 못한다
- 클립보드 성공을 확인했을 때만 성공 메시지를 표시한다. 권한 거절/미지원이면 텍스트를 선택해 수동 복사할 수 있게 안내한다

검증: `python -m unittest discover -s tests` 및 `node tests/test_daily_render.cjs`, `node tests/test_dashboard_period.cjs`, `node tests/test_review_copy_ui.cjs`. 실행 환경의 `ALL_PROXY=socks5h://…` 때문에 기존 httpx 테스트가 실패한다면 테스트 실행에만 해당 프록시 변수를 제외한다. 실제 서비스 설정은 변경하지 않는다.
